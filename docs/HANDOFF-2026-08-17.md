## 2. Open work, highest value first

### A. Normalized-path collision fix (MEDIUM, peer-reviewed, spec complete)

`dv_labeler.build_index_and_paths()` does:

```python
for r in rows:
    p = normalize_path(r.get("path"), mappings)
    if p:
        idx[p] = r.get("dv_layer")        # last row wins, silently
        norm_to_path[p] = r.get("path")
```

311 normalized keys in live data have DISAGREEING `dv_layer` within
`source='scan'`, every one `<real layer> vs unknown`. All 311 currently resolve
to the real layer — **accidentally**. `get_dv_scans()` orders `last_seen_at DESC`
and the loop overwrites, so the OLDEST row wins; it works only because the older
row happens to hold the determinate layer. A rescan can flip it.

**The rule (from review, and do not deviate without re-reviewing):**

```
one unique authoritative layer + unknown(s)  -> that layer
all authoritative layers identical           -> that layer
zero authoritative layers                    -> unknown
multiple DIFFERENT authoritative layers      -> explicit CONFLICT, behave
                                                non-authoritatively (as unknown)
```

* `none` is **authoritative** (detector ran, found no DV). `unknown` is failure.
* **Do NOT use `last_seen_at` to arbitrate two real layers.** `upsert_dv_scan()`
  lets a failed `unknown` scan preserve the old layer while advancing
  `last_seen_at`, so that timestamp does not date the layer. A `layer_observed_at`
  column would be needed first.
* **Do NOT use `_LAYER_RANK`.** That ranks parts of one Plex title, not two
  observations of one file.
* Choose a whole **row**, not a layer from one row and a raw path from another —
  `norm_to_path` feeds the `rating_key` back-annotation.
* Same pattern exists in `build_index()` and the `seed_index` comprehension. Fix
  all three with one shared aggregator; do not fix one and leave the others.

Tests required, **permutation invariance is the point**: `[fel, unknown]` and
`[unknown, fel]` must both give `fel`; `[fel, mel]` both ways must give conflict;
`norm_to_path` must follow the winning row; and a conflict must neither remove a
label nor back-write `rating_key`.

  aggregation, and it fails safe on purpose.

## 3. How to work on this

**This section exists because of the mistakes below. Read it before the mistakes.**

### Verify against the CONSUMER, always

Before reporting any measurement, run it through the **actual production
function**, not a reimplementation in a throwaway query. Every error in section 4
would have been caught by this one rule.

```
WRONG:  SELECT ... WHERE path LIKE '%4k%'        (my guess at what the code does)
RIGHT:  from backend.rename.dv_paths import normalize_path   (what it does)
```

### State confidence explicitly

Mark every claim **measured / inferred / assumed**. If it is inferred, say what
would falsify it. A number with no provenance is an opinion.

### Peer review BEFORE reporting, not after

Two findings this weekend reached the owner as fact and were retracted. If a
finding is going to change what he does, get it checked first. He relays to
ChatGPT by hand; the loop costs him a copy-paste and it has caught five real
things.

### Smaller steps, more checkpoints

Long investigation chains compound an early wrong turn. Stop and confirm.

### Owner-specific, non-negotiable

* **He is not a programmer.** Plain language, expand jargon, lead with what it
  means for him. Plain is not vague — keep real numbers.
* **Every question and every decision that is his goes in an AskUserQuestion**,
  recommendation first, with the downside stated.
* **Jesse-only:** merge, deploy, force-push, mark-ready, prod settings, enable.
* **Never repurpose a credential found on disk without asking** — every time.
* He is usually on **Android**. `SendUserFile` never arrives; links and
  pasteable text only.
* `docker-compose.yml` carries the DV ingest key and `127.0.0.1:9721:9721` as
  **uncommitted** edits. `git add -A` sweeps them in; `git stash` swallowed them
  once. Check `grep -c '9721:9721'` after any git operation.

### Environment traps that cost time this weekend

* `docker` writes to stderr, so **PowerShell 5.1 reports failure on success**.
  Never check `$?` — verify the outcome.
* A `git push` run from the wrong branch **reports success and moves nothing**.
  Verify with `git ls-remote`.
* Backticks in a `git commit -m` string get executed. Use `--file=-` with a
  quoted heredoc.
* Mutation-testing harnesses must purge `__pycache__` between mutants — two
  same-size writes in one second reuse stale bytecode and read as SURVIVED.
* The API has **no `/api` prefix**. Routes are `/download/...`. `/api/...` falls
  through to the SPA catch-all and returns 405, which looks like an auth error.
* `schtasks` is not visible to a non-elevated shell — it returns Access Denied,
  which looks identical to "not registered".

## 4. Mistakes I made, so they are not repeated

All four are the same shape: **I measured a proxy for the consumer instead of the
consumer.**

1. **"Zero items at different resolutions."** I classified resolution by
   searching for `4k` in the path. Every scanned file lives under a folder named
   `4K Columbo` / `4K Drives`, so all 10,548 rows were labelled 4K — including
   ones whose filenames say `1080p`. The output printed a negative count and I
   did not stop.
2. **"The dv_label_vocab setting is a live mismatch."** I read the config field
   and assumed it flowed through. The loader filters any value not in
   `_LAYER_LABELS` and merges over defaults, specifically so a typo cannot strip
   labels. The setting is inert. **No change needed.**
3. **"577 lost DV detections, 42 lost FEL."** Graded HIGH by peer review on the
   strength of my numbers, then withdrawn. I measured raw string equality;
   `normalize_path()` already unifies separators, casefolds AND rewrites drive/UNC
   roots, and both sides go through it.
4. **"The hold release needs a login."** It returned 405, which I read as auth.
   It was my wrong URL. The conclusion happened to be right for the wrong reason,
   which is worse than being plainly wrong.

Also worth carrying: **four separate tests this weekend verified nothing** — a
fixture whose INSERT silently failed so assertions ran against an empty table, a
test asserting on a docstring, a modelled barrier test that reproduced the
locking pattern instead of exercising it, and a JD double that returned `None` on
its success path so neither direction of the contract was pinned. Mutation
testing caught three of the four. **Run it.**
